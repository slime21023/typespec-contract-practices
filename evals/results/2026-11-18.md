## Round H: contract organization best practices (SKILL.md §2 rewrite)

The skill now defines:
- a single entrypoint that imports module directories
- modules always split into `resource`, `requests`, `responses` and `operations`
- `<Service>.<Capability>` module namespaces
- explicit camelCase operation IDs for new contracts
- one-way dependencies between files

Before writing, the organization was compiled on an older and a current compiler release. Directory imports, module schema names (`Books.Book`), parent-namespace references, fully qualified cross-module references, `@useAuth` coverage, `@operationId` output and `@versioned` with module `@added` all behaved the same on both. The reference example compiles as extracted from the document.

`uc6-multi-resource` is new. Its prompt does not name `_contract/`.

| Case | Haiku | Sonnet | Structure review |
| --- | --- | --- | --- |
| uc1 | 10/10 | 10/10 | Both follow §2. |
| uc5 | 6/6 | 6/6 | Both kept the `Orders` namespace in the copy. Haiku emitted `Orders_getOrderHistory`; Sonnet added `@operationId("getOrderHistory")` next to `Orders_` defaults. |
| uc6 | 4/4 | 4/4 | Both chose `_contract/` unprompted and follow §2. Haiku had one compile failure (missing `@typespec/openapi` import). Sonnet added a `common/pagination.tsp` model that no module used. |

The rules were then clarified:
- New operations in an existing or copied contract follow its operation ID style.
- `common/` holds only definitions that two or more modules use.

## Compile retries

Earlier rounds did not record failed attempts consistently. Reports from Rounds B and D mention these failures:

- object values written as `{ }` instead of `#{ }`
- `version` passed to `@service`
- `@info` used without `@typespec/openapi`
- an invalid `\.` escape
- an unknown `@deprecated` decorator
- a missing import

The worst single run had 3 failed compiles, and one run hit 4 errors on its first compile. Across the 12 skill runs in Rounds E and E2, there was one failed compile: a missing `@typespec/http` import in a new file.
